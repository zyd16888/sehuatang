# 通用抓取与批量保存流水线

用户确认：2026-09-09，按“请求前去重 → 并发抓取/解析 → 有界队列 → 批量写入”实施。

## 合同

- 默认每批 10 个目标，首条进入缓冲后最多等待 1 秒开始落库；页结束强制提交尾批。
- 写入线程独立计时，不依赖下一个抓取结果到达；数据库变慢时通过有界队列反压。
- 请求前按站点既有 new_only/stale_after/refresh_all 策略过滤；待确认批次按帖子 key 去重。
- 仅幂等资源写入重试瞬态连接故障；失败台账计数不盲目重放；写库/台账失败不推进页检查点。
- 成功写入后批量清理失败台账。正常停止冲刷已进入队列的数据；强杀后由未完成页重新发现。
- 不增加 Redis，不并行列表页，不改变代理/CF/限流配置，不执行生产补抓或生产数据写入。
